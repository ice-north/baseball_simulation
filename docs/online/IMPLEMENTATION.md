# オンライン疑似ペナント 初版

## 合意した範囲

- 操作対象は固定4球団（人間2人、CPU2球団）。既存の背景球界・試合計算を利用する。
- 日本時間 08:00 / 10:30 / 13:00 / 15:30 / 18:00 / 20:30 / 23:00 に1日ずつ進行する。
- 契約・補強・キャンプは両者の提出を待つ。休止中の予定枠を後からまとめて消化しない。
- PCは詳細操作、スマホは専用の簡易Webビュー。判定・保存処理は共通にする。
- 通常の試合は自動消化。トレード・監督移籍・途中参加・既存セーブ移行は初版の対象外。
- 一人用モードは維持する。オンラインの正本はサーバーとし、個人の手動ロード・早送りは受け付けない。
- 基本は取り込み用PRを1本にまとめ、段階ごとの日本語コミットで区切る。

## 実装順と受入条件

| 段階 | 内容 | 受入条件 |
| --- | --- | --- |
| 1 | 日次処理の共通化、二人の球団所有、スナップショット | 画面なしで1日進行し、CPU処理が人間2球団を変更しない |
| 2 | 共有保存、認証、API、再送・版の確認 | 他球団・旧端末・古い版からの更新を拒否し、重複処理を防ぐ |
| 3 | 契約・補強・キャンプ・年度更新 | 二人の提出と球界全体の処理をそれぞれ一度だけ実行する |
| 4 | 定時実行・休止・障害復旧 | 不在でも進み、停止理由が分かり、停止分を一括消化しない |
| 5 | PCオンライン画面 | 必須の詳細操作を共有APIで完了できる |
| 6 | スマホ簡易画面 | 結果・順位・簡易編成・提出確認をスマホ幅で完了できる |
| 7 | 通年・復元・公開環境の受入 | 実試合を経て2年目を開幕し、同じ状態へ復元できる |

## 外部作業の扱い

Vercel / Supabaseのアカウント作成、プロジェクト作成、認証情報、実公開、実機確認は
必要になった時点で残件として分離する。アカウントを要求してローカルの実装を停止しない。
ローカル成功を実サービス成功・スマホ実機成功として報告しない。

## 機能単位のレビュー

各機能で、変更箇所の読み直し、境界・失敗時の確認、必要な回帰検証、問題修正を行う。
結果は `REVIEWS.md` に残す。既存の `npm run check:full` / `npm run build` と
オンライン用の通年・再送・復元・権限・表示検証を区別する。
