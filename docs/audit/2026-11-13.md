## 判断がほしいもの

1. **トレードで複数人をもらうときの「穴」の値段**（`tradeJudge.needFactor`）
   - いまは1人ずつ「ほかは残る」として値段を付けている。外野のレギュラー2人をまとめてもらうと、2人抜けた大きな穴に上乗せが掛からない。
   - おすすめ: もらう全員が抜けたときの落ち込みで1回だけ計算する（サーバーと見込みメーターの両方）。
2. **キャンプの伸びの直しで数値が変わる**
   - 上の表のとおり、高い能力（65以上）の伸びが前より小さく、78以上は0から少し伸びるようになった。もともと書かれていた意図（65から鈍る・崖にしない）に合わせた形。
   - おすすめ: このまま。年をまたいだ能力の分布は、次の `check:full` で見る。
3. **初期メンバーセットの選手の詳細**
   - 表から列を落とした理由が「残りは名前を押せば見られる」だったが、セットの選手は詳細を削って送っており、回復・球種などが「—」になる（`projection.mjs` の `packView`）。
   - おすすめ: セットの選手も詳細を取りに行けるようにする。
4. **キャンプの検査が1つの世界でしか測っていない**
   - 本物のリーグは作った時刻から種を決めるので、検査が測った世界とは違う。
   - おすすめ: online-camp-check で種を3つほど足し、平均が収まるかを見る（検査が約1分延びる）。
5. **アプリの能力の色**
   - Web は F（0〜39）を3段に分けたが、アプリは1色のまま。
   - おすすめ: アプリも分けてそろえる。

## 直していないもの（記録だけ）

- トレードの調子の補正（`formFactor`）は `seasonStats` で見ている。記録がそろった年の画面は記録の成績を出すので、シーズン途中に移った選手で、画面の成績の札と判断の ±8% が食い違いうる（ありそう、未確認）。
- 見込みメーターの「値 高・中・低」は、CPU球団の事情込みの値段と素の値段を1つの山で切っているので、自軍の選手が低めに出やすい。
- `needFactor` が選手ごとに `squadStrength` を2回計算し直している。捕手の数え方だけ `isActive` で絞っていない（いまのオンラインでは害なし）。
- アプリのホームの「何号」は選手の今季成績から逆算している。記録の `seasonHomeruns` を使えば Web とそろうが、記録が途中からの年はいまのアプリのほうが正しい。
- アプリの走力の換算式が3か所（`Camp.kt`・`Text.kt`・`Tryout.kt`）にある。
- `planCount` は検査だけが使う。`plannedPicks` の `roster` 引数は使われていない。
- `getReleasedCandidatesFromPool`: 元プロがプールに足りない年は、新球団ごとに同じ顔ぶれを引く（影響は小さい）。
- スマホの Web のホームも「リーグの話題」が2件になった（PCの1画面の決まりに合わせた変更の巻き添え）。続きは球団史・記録で読めるようになったので、そのままにした。
