## 大きな整理の候補（持ち主の判断。価値の高い順）

いずれも動きは変えない前提だが、量が多いので1つずつ PR にする。

1. **（前提）固定の種で試合と1年を回し、結果のハッシュを前後で比べる検査を作る**。いまの `check:season` は乱数を固定しないので、「動きを変えない移動」を証明できない。今回の整理はその場で作った比べ方で確かめた。→ おすすめ: 最初にこれ。以下の全部の安全網になる。
2. **オンラインの書き込みのたびに、リーグ全体で同じ項目（順位・リーダー・12球団の戦力・球団史など）を参加者の人数ぶん作り直している**（最大12回＋返事用に1回）。版の鍵で1回だけ作って参加者の部分だけ足す。速さに効く（中規模・危険は低〜中）。
3. **App.jsx（4371行）から采配の試合を切り出す**（約3000行を `useManualGame`・`ManualGameScreen` へ）。采配の試合を通る画面の検査が無いので危険は高い。先に書くだけの状態4つ（`gameSetup.js` から外す必要がある）を片付ける。
4. **1球の計算が2つある**（采配: App.jsx の `simulateSinglePitch`／自動: `simulateOnePitch`）。スタミナの効き方とカウントの補正がもう違う。どちらの数字を正にするかを決めて1つにする（采配の数字が変わる）。試合後の成績の書き込みの2つも同様。
5. **autoSimulation.js（3286行）を分ける**: CPU の打順・疲労回復／継投の判断（約800行。打席の間とイニング終わりで約60行の写し）／成績の書き込み。
6. **leagueEngine.mjs（2971行）を受け持ちごとに分け、leagueService の命令（約450行の if の連鎖）を表にする**（命令ごとの属性が4つの一覧に散っている）。
7. **年度末と開幕の手順を一人用とオンラインで1つに**（一人用は ManagementScreen・GameFlowScreens に計7回写してある）。
8. **LineupSettingScreen の従来の画面（`!board`。約1000行）**: いまはオンラインのスマホ版の投手起用のためだけに残っている。スマホを投手起用のタブだけにするか、新しい表の縦の形にすれば消せる。
9. **一人用の表（Solo*Board）とオンライン PC の表の中身を共通に**（選択・ドラッグ・メニューの位置の処理の写し、約400行）。投球回の書き方（「18.2」と「18 2/3」）もそろえる。
10. **tryoutSystem.js・universityPool.js・scoutingSystem.js を分ける**（選手を作る部品が「トライアウト」に住んでいる依存の絡み）。
11. **アプリの残りの手写し（能力の説明・成績の列・守備の段など）とビューの約束を生成に**。今は正規表現で Kotlin を読んで照合している。
12. **検査**: 画面検査2本が `online-records-check` を丸ごと（約52秒）読み込みで走らせている → 作る部分を lib に切り出す。リーグを1年進める繰り返し5本を1つの道具に。
13. **CPU の采配の決まりを一人用の采配試合（aiManager.js）と自動試合でそろえる**（継投・守備固めの決め方が違う。動きが変わる）。
