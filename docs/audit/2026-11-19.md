## 判断がほしいもの

1. **ログイン前の招待の確かめが、毎回保存の芯（最大約9MB）を読む**（`server/leagueService.mjs` の `checkInvite`）。合言葉は当てられないが、形だけ合う文字列を送り続けると Supabase の転送量と関数の時間を外から使わせられる。案: 招待を control の行（`sessions` と同じ段）か小さな別ファイルへ移して芯を読まずに確かめる（おすすめ。招待を作るたびに全員のビューを作り直す件も一緒に消える）／IP ごとの回数制限。
2. **空きが1球団なのに招待リンク2本で2人ともアカウントを作れる**（後の人は参加できずアカウントだけ残る。`server/invites.mjs` の `claimInvite`）。案: 使用済みでまだ参加していない招待を空きから引く（おすすめ。ただし参加しないままの人がいると枠が埋まったままになる）／今のまま。
3. **永久欠番にしたい番号が、すぐ別の選手に付いてしまう**（PR #44。引退したエースの #18 は次の投手に振られ、「いま○○が付けています」で欠番にできない）。案: (a) 付けている人がいても欠番にでき、その人の番号を振り直す（おすすめ。今の番号の振り直しの仕組みで済む）／(b) 引退した人の番号をそのオフの間は空けておく。
4. **一人用で「役割なし」の投手をクローザーにすると、前のクローザーが「役割なし」に落ちる**（PR #43。オンラインには役割なしが無い）。案: 前のクローザーは「おまかせ（救援）」にする（おすすめ）／今のまま。
5. **投手起用の「変化」の列が、封印した球も数える**（一人用・オンラインとも。試合では封印した球を投げない）。足しているのは球種の `level`（キレ・習熟度）で、見出しの説明は「変化量の合計」。案: 封印した球を除き、説明を「球種のキレの合計」にする（おすすめ）／今のまま。
6. **能力の上限が99のもの（年齢の伸びの `STAT_GROWTH`）と100のもの（キャンプの制球・筋力など）が混ざっている**。案: どちらかへそろえる（99 にそろえると今100の選手が出る経路を止めることになる）／今のまま。
7. **すでに上限を超えた保存（体力118・疲労2000超など）は下がらない**。案: オンラインは版を上げて1段で上限へ丸める・一人用はロード時に丸める（おすすめ）／今のまま（新しく超えることはない）。
8. **オンラインでは高校の最上位層がプロへ抜けないので、逸材枠が一人用より強く出うる**（オンラインのプロ指名は年0〜3人）。案: 長期シミュで逸材枠の評価を一人用と比べて決める（おすすめ）／今のまま。
9. **投手起用の表の部品が一人用とオンラインに2つある**（`SoloPitchingBoard.jsx` と `PitchingBoard.jsx`。今回の能力の列の変更も2つの PR が別々に入れていた）。案: #43・#45 が入ったあと、見出しと行を1つの部品にまとめる（おすすめ）。
